Replaces v0.1.0, whose package could not complete its first install.

## What was wrong with v0.1.0

Two defects, found one after the other by installing the published package on a clean Ubuntu 24.04 with
its own Docker daemon and running the install end to end.

**The image build failed.** The commit that added the Apache licence pointed the package metadata at
`LICENSE`, and the Dockerfile copies only `pyproject.toml` and `README.md` before its first dependency
install, so the build stopped with `License file does not exist: LICENSE`.

**The infrastructure could not start.** MinIO has withdrawn its Docker Hub repositories, so
`minio/minio` and `minio/mc` no longer resolve, and every fresh install stopped at "Starting
infrastructure" with `pull access denied`. This was not specific to the package: every git clone on a
machine without cached images failed the same way, and it is why the CI `test` job had been failing. The
machine this project is developed on kept working off copies cached almost two years earlier.

## What changed

- The Dockerfile copies the licence before installing, and a test fails if the package metadata ever
  names a file that step does not copy.
- MinIO images come from quay.io. It is the same release and the same image: identical image IDs, and
  the same MinIO commits. The backup and restore scripts, which pulled `minio/mc:latest` from the
  withdrawn repository, are pinned to the same release.
- `scripts/check_images.py` resolves every image a fresh install pulls, and the release workflow runs it.
- The release workflow now installs the package on its runner and brings the whole product up before it
  publishes anything, checking the API, the web app, and a request with the generated admin token. The
  v0.1.0 checks only installed the package and ran its launcher, which both defects passed.

## Verified for this release

From an empty image cache on a clean Ubuntu 24.04, with no GPU available:

| | |

| package dependencies | resolved by `apt` from Ubuntu's own `docker.io` and `docker-compose-v2` |
| first install | about 6.5 minutes |

## What LabeloxAV is

An annotation and data engine for autonomous driving, built around Indian roads: auto-labelling behind a
confidence gate, human review, tracking, 3D from LiDAR or estimated depth, HD map export, and dataset
export in COCO, YOLO, KITTI and OpenLABEL. The package ships the source tree under `/opt/labeloxav` and a
`labeloxav` command; the product runs as Docker containers built from that tree.

Honest state: 600,133 labels in the reference corpus, 788 with a human verdict. The HD map runs end to end
but two of its outputs are not yet trustworthy, as the documentation says. Apache License 2.0.
